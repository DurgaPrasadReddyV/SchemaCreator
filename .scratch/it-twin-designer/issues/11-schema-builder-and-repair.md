# 11 — Schema builder `/schema` + repair conflicts (seam 2, part B)

**What to build:** The schema-evolution surface at `/schema`, using `@dnd-kit/sortable` + AntD (`Card`/`Form`/`Select`/`Switch`/`Cascader`/`TreeSelect`; use @dnd-kit, not react-dnd). A Type is Sections + Fields: Section = sortable `Card`, Field = sortable `Form.Item`-row, add-actions are `Button type="dashed"`, reference target via `TreeSelect` of Types. Field types: `text`, `enum`, `multi-tag`, `boolean`, `number`, `ref`. A relation-type manager lives as a section within `/schema` (so the relation vocabulary evolves without a separate screen) — each relation type declares a direction semantic (forward/reverse/bidirectional) and a `propagatesReachability` flag, with type-constrained source/target and human labels in both directions. Capability flags (id + label + badge style + default home) and data-categories (with implied default classification + recommended capabilities) are user-extensible here. **Hybrid schema evolution:** safe evolutions (add a field, rename a field's label, move/reorganize Sections) are free — added fields absent on existing objects lazy-default, renames are free because values are id-keyed, section moves are free. **Destructive evolutions** (remove a field → orphaned keys; change a field's type → possibly invalid values) surface a per-Type **"Repair objects"** action listing the affected objects and the specific conflict, reviewable before any data is discarded or transformed. **No silent data destruction.** This ticket delivers **seam 2 part B** — the conflict-detector tests live here (`detectRepairConflicts(schema, objects)` → per-Type conflict list).
